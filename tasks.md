We’ll take it one stage at a time. The plan is:
1. Prepare the VPS: update Ubuntu, create a separate deployment account, and configure the firewall while keeping SSH access working.
2. Point the subdomain: add an A record for sweetia.mohamad.tn in the DNS settings where mohamad.tn is managed. You don’t need to move the domain to OVH.
3. Install the app stack: set up Nginx, the PHP version and extensions your Laravel project requires, MySQL, and the tools needed to build the Vue assets.
4. Deploy Sweetia: configure production environment variables and the database, build the frontend, and verify the site works over HTTPS. Laravel’s deployment guide specifically covers serving from the public directory, writable storage permissions, production settings, and optimization. Laravel deployment guide
5. Set up a repeatable update process: keep developing on dev and treat main as the version that goes live. After changes are reviewed and merged into main, GitHub Actions runs `.github/workflows/deploy-production.yml`. The VPS deploy script backs up the database and uploaded files before installing dependencies, building assets, migrating, refreshing Laravel caches, and restarting the queue and Reverb services. Configure the GitHub SSH secrets and the limited VPS service-restart permission before merging the workflow into main. The deployed VPS currently follows `codex/laravel-12-upgrade`, so promote that branch through dev and into main only after its VPS validation is complete.
6. Set up backups for the database and uploaded files. `scripts/backup-sweetia.sh` creates compressed, verified backups, keeps the latest 14 days on the VPS, and is also run automatically before each production deployment. Schedule it daily and configure an offsite copy so backups remain available if the VPS is lost.
